# Эфир

Веб-аналог Discord: комнаты с текстовыми и голосовыми каналами, разговор
по микрофону и трансляция экрана с переключением качества. Всё поднимается
одним файлом — `main.py`.

## Запуск

```bash
python main.py
```

Скрипт сам доставит недостающие пакеты, создаст базу `instance/efir.db`,
заведёт администратора и стартовую комнату. Дальше открываете
<https://localhost:2079> (HTTPS включён по умолчанию).

Для локальной работы без предупреждения о самоподписанном сертификате:

```powershell
.\.venv\Scripts\python.exe main.py --local --http
```

Тогда адрес — <http://localhost:2079>. На localhost микрофон работает и по HTTP.
Исправления и результаты проверки описаны в [CHECK_REPORT.md](CHECK_REPORT.md),
настройка связи через интернет — в [DEPLOYMENT.md](DEPLOYMENT.md).

Вход администратора: **admin / 123Alex12**
Админ-панель: <https://localhost:2079/admin>

Всё настраивается в `settings.json` рядом с `main.py` — он создаётся при
первом запуске. Флаги нужны, только чтобы разово отступить от настроек.

```json
{
  "host": "0.0.0.0",
  "port": 2079,
  "https": true,
  "cert_hosts": [],
  "debug": false
}
```

`host` — `0.0.0.0` доступен по IP компьютера, `127.0.0.1` только локально.
`https` включён, потому что без него браузер не отдаёт микрофон и захват
экрана никому, кроме localhost. `cert_hosts` — домен или внешний IP, если
нужно вписать их в сертификат.

### Ключи запуска

| Ключ | Что делает |
|---|---|
| `--port 8080` | другой порт на один запуск |
| `--local` | слушать только этот компьютер |
| `--host 192.168.1.50` | привязаться к конкретному интерфейсу |
| `--http` | выключить HTTPS на один запуск |
| `--reset-db` | снести базу и создать заново |
| `--debug` | автоперезагрузка при правках кода |

По умолчанию сервер слушает все интерфейсы (`0.0.0.0`), так что он сразу
доступен по IP компьютера. При старте адрес в локальной сети печатается
в консоль — сверяйтесь с ним.

## Не открывается по IP

Проверяйте по порядку — почти всегда дело в первых двух пунктах.

**1. На каком адресе висит сервер.** Запустите при работающем сервере:

```
netstat -ano | findstr :2079
```

Должно быть `0.0.0.0:2079`. Если там `127.0.0.1:2079`, сервер слушает только
петлю: до него не достучится ни другой компьютер, ни роутер, и проброс портов
тут ничем не поможет. Уберите ключ `--local`, если он был.

**2. Брандмауэр Windows — самая частая причина, когда локально работает,
а снаружи нет.** Петлевой трафик он не фильтрует, а входящие извне режет.
Первый запуск обычно показывает окно с вопросом; если его закрыли крестиком,
Windows создаёт правило запрета и дальше блокирует молча.

Запустите `open-port.bat` из папки проекта — он сам попросит права
администратора и добавит правило. При старте сервер проверяет, есть ли оно,
и напоминает, если нет.

Проверить вручную: «Монитор брандмауэра Защитника Windows» → «Правила для
входящих подключений», ищите `Efir 2079` и убедитесь, что нет запрещающего
правила для `python.exe`. То же самое из консоли администратора:

```
netsh advfirewall firewall add rule name="Efir 2079" dir=in action=allow protocol=TCP localport=2079
```

**2а. Профиль сети.** Если подключение помечено как «Общедоступная сеть»,
правила для частной сети не действуют. `open-port.bat` создаёт правило
с `profile=any`, так что это учтено.

**2б. Проверяете снаружи, находясь внутри?** Обращение к своему внешнему IP
из домашней сети работает не на всех роутерах — нужна поддержка NAT loopback.
Проверяйте с телефона по мобильному интернету, а не с того же Wi-Fi.

**2в. Адрес с https://.** Если в настройках `"https": true`, а вы открываете
`http://адрес:2079`, соединение оборвётся без внятной ошибки. Схема должна
совпадать.

**3. Порт уже занят.** `netstat -ano | findstr :2079` покажет чужой процесс —
возьмите другой порт ключом `--port`.

**4. Микрофон и экран не работают, а чат работает.** Это не сеть, см. раздел
ниже — нужен HTTPS.

**5. Звук не проходит между конкретными людьми.** Медиа идут напрямую между
браузерами. Если оба участника за строгим NAT, одних STUN-серверов мало —
нужен TURN. Его настройки задаются в `settings.json` или переменными окружения,
см. [DEPLOYMENT.md](DEPLOYMENT.md). Править JavaScript больше не нужно.

Если сервис виден из интернета, первым делом смените пароль `admin`: админка
даёт полный доступ к базе и SQL-консоль.

## «Requested device not found» при входе в голосовой канал

Это ответ браузера `NotFoundError`: в системе нет устройства записи. Чаще
всего так и есть — на стационарном ПК без гарнитуры микрофона просто нет.
Проверьте «Параметры» → «Система» → «Звук» → «Ввод»: если список пуст,
дело не в сайте.

Заход в канал при этом не блокируется: вы попадаете внутрь в режиме
прослушивания — других слышно, трансляции видно, у остальных рядом с вашим
именем горит перечёркнутый микрофон. Когда гарнитура появится, нажмите
кнопку «Нет микрофона» на панели: дорожка подменится на лету, перезаходить
в канал не нужно.

Другие варианты той же кнопки: `NotReadableError` — микрофон занят другой
программой; `NotAllowedError` — доступ запрещён в настройках сайта, значок
слева от адреса в браузере. Ещё проверьте «Конфиденциальность и защита» →
«Микрофон» в параметрах Windows: там есть общий выключатель для приложений.

## Микрофон и трансляция требуют HTTPS

Браузеры дают `getUserMedia` и `getDisplayMedia` только в защищённом
контексте. `localhost` считается защищённым всегда, а `http://` по IP —
никогда, независимо от настроек. Отсюда сообщение «Браузер не даёт доступ
к микрофону». Чат при этом работает: ему защищённый контекст не нужен.

Три пути, от самого быстрого к самому правильному.

### Как убрать предупреждение браузера

Самоподписанному сертификату браузер не верит: имя в нём правильное, а вот
издателя он не знает. Отсюда «Невозможно установить безопасное соединение».
Три способа, от простого к правильному.

**1. Добавить сертификат в доверенные — на каждом устройстве.** На Windows
запустите `trust-cert.bat` из папки проекта: он попросит права администратора
и положит `instance/cert.pem` в «Доверенные корневые центры сертификации».
После этого браузер нужно закрыть полностью и открыть заново.

У Firefox своё хранилище: «Настройки» → «Приватность и защита» →
«Сертификаты» → «Просмотр сертификатов» → «Центры сертификации» → «Импорт»,
галочка «Доверять при идентификации веб-сайтов».

На Android: скопируйте `cert.pem`, «Настройки» → «Безопасность» →
«Шифрование» → «Установка сертификатов» → «Сертификат ЦС». На iOS: отправьте
файл на устройство, установите профиль, затем «Настройки» → «Основные» →
«Об этом устройстве» → «Доверие сертификатам» и включите переключатель.

Удалить потом: `certutil -delstore Root "Efir Local"`.

Имейте в виду: сертификат выпущен как корневой, поэтому машина, где он
установлен, будет верить всему, что подписано ключом из `instance/key.pem`.
Держите этот файл при себе и не раздавайте вместе с `cert.pem`.

**2. Домен и настоящий сертификат — предупреждений не будет нигде.** Для
IP-адреса публичный сертификат не выдают, а для имени — да, и оно спокойно
может указывать на адрес в локальной сети. Возьмите бесплатное имя на
DuckDNS, направьте его на нужный адрес и получите сертификат Let's Encrypt
через проверку по DNS. Готовые файлы пропишите в `settings.json`:

```json
"cert_file": "C:/certs/fullchain.pem",
"key_file":  "C:/certs/privkey.pem"
```

Сервер возьмёт их вместо самоподписанного. Проще всего это делает Caddy —
он получает и продлевает сертификат сам:

```
efir.example.com {
    reverse_proxy 127.0.0.1:2079
}
```

**3. Cloudflare Tunnel — без домена и без проброса портов.** Даёт готовый
адрес с настоящим сертификатом и работает откуда угодно, но весь трафик идёт
через Cloudflare.

**Свой сертификат — включён по умолчанию.** Ничего делать не нужно:
в `settings.json` стоит `"https": true`.

Сертификат выпускается один раз и лежит в `instance/cert.pem`, так что при
перезапусках сервера принимать его заново не придётся. В него попадают
`localhost`, `127.0.0.1` и адрес компьютера в локальной сети; для внешнего
домена или белого IP добавьте его в `cert_hosts` в `settings.json`.

В сертификат попадают `localhost`, `127.0.0.1`, имя компьютера и все его
адреса в сети — чем больше имён сразу, тем реже сертификат перевыпускается,
а перевыпуск сбрасывает выданное доверие. Для внешнего домена добавьте его
в `cert_hosts`.

**Флаг Chrome — если не хочется возиться с сертификатом.** Откройте
`chrome://flags/#unsafely-treat-insecure-origin-as-secure`, впишите
`http://192.168.1.50:2079` со своим адресом, включите и перезапустите
браузер. Тогда микрофон и экран работают по обычному `http://`. Настраивать
нужно на каждом устройстве, для домашней сети это нормально.

**Настоящий сертификат — если сервис постоянный.** Свой домен и обратный
прокси, например Caddy, где весь конфиг — три строчки:

```
efir.example.com {
    reverse_proxy 127.0.0.1:2079
}
```

Caddy сам получит сертификат Let's Encrypt и будет его продлевать,
предупреждений не будет ни у кого. Альтернатива без своего домена —
Cloudflare Tunnel: он даёт готовый HTTPS-адрес и не требует проброса портов.

## Что умеет

**Комнаты и каналы.** Комната — это набор каналов, как сервер в Discord.
Создать может любой; при создании включается пароль или комната остаётся
открытой. Внутри — текстовые каналы (`#`) и голосовые (🔊). Владелец
добавляет и удаляет каналы, удаляет комнату; остальные могут выйти.

**Чат.** Сообщения пишутся в текстовые каналы и хранятся в базе. История
подгружается порциями по 50 при прокрутке вверх. Есть индикатор набора
текста, удаление своих сообщений, ссылки кликабельны. Вложений нет — по
условию задачи.

**Личные папки.** Комнаты в левой колонке можно раскладывать по папкам и
менять местами: тяните за ручку слева от названия. Раскладка своя у каждого —
хранится за учётной записью и другим не показывается. Удаление папки комнаты
не теряет: они возвращаются на верхний уровень.

**Профиль.** Нажмите на себя внизу левой колонки: имя в чате, цвет подписи,
смена пароля и аватарка. Картинка ужимается браузером до квадрата 256×256 и
уходит на сервер уже маленькой; файл кладётся в `instance/avatars`, прежний
удаляется сразу же. Формат определяется по первым байтам файла, а не по
расширению, размер ограничен 400 КБ. При старте сервер подчищает файлы, на
которые никто не ссылается.

**Кто в сети.** У каждого в списке участников горит точка: зелёная, если
человек сейчас открыл приложение. Несколько вкладок считаются как одна
сессия — статус гаснет, когда закрылась последняя.

**Каналы.** Владелец, модератор и админ переименовывают каналы карандашом и
меняют порядок перетаскиванием за ручку. Это общее для всех: изменения сразу
разлетаются по комнате. Текстовые и голосовые местами не меняются, иначе
канал сменил бы раздел.

**Выгнать, исключить, убрать.** Три разные вещи в карточке участника.
«Выгнать» выставляет из голосового канала, вернуться можно сразу.
«Исключить» вдобавок закрывает вход в этот канал. «Убрать из комнаты»
снимает участие: открытую комнату человек откроет заново сам, в закрытую
войдёт по паролю. Права везде одинаковые — владельца и админа сайта
не трогает никто, модератор работает только с обычными участниками.

**Исключение и запрет входа.** В карточке участника, если он сейчас в вашем
голосовом канале. Владельца и админа сайта исключить нельзя; модератор
трогает только обычных участников. Исключение сразу закрывает вход в этот
канал — иначе человек вернулся бы через секунду. Снять запрет можно там же:
нажмите на участника в списке справа, в карточке появится строка с каналом
и кнопкой «Снять». Владелец и админ снимают любые запреты, модератор —
только собственные. Запреты переживают перезапуск и видны в админке.

**Гости.** На странице входа есть «Войти как гость»: заводится временная
учётка без пароля, живёт неделю и убирается при старте сервера, если гость
ничего не написал. Как только гость выходит или закрывает страницу, его
участие в комнатах снимается — из списков он пропадает, а написанное
остаётся. Между закрытием вкладки и уборкой есть минута, иначе обычная
перезагрузка страницы выкидывала бы гостя из комнат. Гости не создают комнаты, не становятся модераторами и не ставят аватарки —
учётка временная, хранить за ней файлы незачем.
У каждой комнаты есть галочка «Пускать гостей» — при создании и в
настройках; выключите, и вход в неё будет только для зарегистрированных.

**Настройки комнаты.** Владелец и админ сайта меняют название, описание
и пароль кнопкой «Настройки» над списком каналов. Пароль можно задать,
сменить или снять совсем. Названия комнат не повторяются, регистр не
учитывается.

**Роли.** Создатель комнаты автоматически становится владельцем. Он может
назначать и снимать модераторов: нажмите на участника в списке справа или
в голосовом канале и поставьте галочку в карточке. Владелец и админ сайта
удаляют комнату; владелец, модератор и админ создают и удаляют каналы.
Админ сайта может всё в любой комнате.

**Тишина в канале.** Владелец или модератор включает галочку «Тишина» на
панели голосового канала. Если нажал модератор — глушатся все, кроме него,
владельца и админа. Если нажал владелец — все, кроме него. Снять может тот,
кто включил, либо владелец. Пока тишина активна, кнопка микрофона у
заглушённых заблокирована и показывает предупреждение. Правило держит
сервер: попытка прислать «микрофон включён» отклоняется, а входящий звук
заглушённых участников отключается и на стороне слушателей — так тишина
работает даже против правленого клиента.

**Поднятая рука.** Кнопка «Рука» на панели голоса. Остальным приходит
уведомление со звуком, а поднявший подсвечивается янтарной рамкой в списке
канала и в списке участников, пока не нажмёт «Опустить».

**Громкость по участникам.** Нажатие на человека открывает карточку. На себе
регулируется громкость собственного микрофона (сигнал идёт через усилитель
WebAudio), на другом — насколько громко его слышно именно вам, от 0 до 200%.
Настройки лежат в браузере и у каждого свои.

**Шумодав.** В своей карточке, под чувствительностью. Работает спектральным
вычитанием: пока вы молчите, накапливается профиль постоянного фона —
вентилятор, гул, шипение — и потом вычитается из каждого кадра. Речь при
этом почти не страдает: у неё энергия в других полосах и меняется во
времени, а фон ровный. На средней позиции фон падает примерно на 70%,
громкость голоса — на пару процентов. На максимуме звук может стать
«подводным», это плата за глубину подавления.

Окно берётся как корень из Ханна — оно применяется дважды, на анализе и на
синтезе, и их произведение при шаге в половину кадра суммируется ровно в
единицу. С полным Ханном на обоих концах сумма перекрытий гуляет от 0.5 до
1.0, и сигнал получает амплитудную модуляцию частотой fs/HOP: голос звучит
металлически, «роботом». Усиление дополнительно сглаживается по соседним
полосам, иначе остатки шума собираются в короткие тоны — музыкальный шум.
Задержка обработки 384 сэмпла, около 8 мс.

Обработка идёт в AudioWorklet, то есть в отдельном аудиопотоке, и не
дёргается от загрузки интерфейса. Если браузер его не поддерживает, звук
идёт без фильтра, ползунок гаснет с пояснением, а связь работает как
обычно. Файл обработчика — `app/static/js/denoise.js`.

**Чувствительность микрофона.** В своей карточке, под громкостью. Это
настоящий шумовой порог: пока уровень ниже отметки, микрофон не передаёт
ничего, поэтому вентилятор и клавиатура не идут в канал. Ниже полоска
уровня — она зеленеет, когда вас слышно, янтарная метка показывает порог.
После спада ниже порога передача держится ещё 280 мс, иначе шумоподавитель
обрубал бы концы слов. Значение сохраняется в браузере.

**Голос.** Заходите в голосовой канал — браузер спрашивает микрофон, дальше
все участники соединяются напрямую друг с другом (mesh). Говорящих видно по
подсветке в списке. Микрофон выключается кнопкой, у остальных он показывается
перечёркнутой иконкой рядом с именем. Вход и выход отмечаются короткими
сигналами: свои — двумя нотами вверх и вниз, чужие — одной тихой. Звук
синтезируется в браузере через Web Audio, никаких файлов проект не тянет.

**Звук с экрана.** Переключается кнопкой «Качество». При показе всего экрана
браузер отдаёт весь системный вывод — вместе с голосами участников, которые
звучат у вас же, и они возвращаются всем обратно. Поэтому по умолчанию стоит
режим «Приглушать при речи»: пока кто-то говорит, дорожка звука экрана
глушится. Дорожка идёт с задержкой 60 мс, так что детектор успевает сработать
до того, как звук уйдёт — не проскакивает даже первый слог. Есть ещё «Не
передавать» (браузер даже не предложит системный звук) и «Передавать как
есть» — последний годится только когда все в наушниках. При показе отдельной
вкладки приглушение не нужно и не включается: там захватывается звук лишь
этой вкладки. Своя вкладка из списка выбора исключена, иначе получилось бы
зеркало.

**Раскладка.** Когда идёт трансляция, экран делится по вертикали: картинка
слева, переписка справа — оба видно одновременно, чат никуда не уезжает.
Кнопка «Развернуть» отдаёт всю ширину картинке. На узких экранах трансляция
уходит наверх с ограничением по высоте, чтобы чат оставался на виду.

**Телефон.** Боковые панели превращаются в выдвижные шторки: слева комнаты
и каналы, справа участники. Поле ввода не меньше 16px, иначе iOS зумит
страницу при фокусе; отступы учитывают вырез экрана; кнопки не мельче 40px.

**Трансляция экрана.** Кнопка «Экран» в голосовом канале. Пять пресетов
качества:

| Пресет | Разрешение | Кадры | Битрейт |
|---|---|---|---|
| Экономный | 1280×720 | 15 | 0,8 Мбит/с |
| Стандартный | 1920×1080 | 30 | 2,5 Мбит/с |
| Высокий | 1920×1080 | 60 | 6 Мбит/с |
| Максимальный | 2560×1440 | 60 | 12 Мбит/с |
| Как в источнике | родное | 60 | 20 Мбит/с |

Качество переключается прямо во время показа — кнопка «Качество» в шапке.
Под капотом это `applyConstraints` на дорожке плюс `setParameters` на
кодировщике каждого соединения. Для чёткого мелкого текста низкие пресеты
используют `maintain-resolution`, высокие — плавность движения. Кодек
выбирается в порядке AV1 → VP9 → H.264 → VP8, если браузер умеет.
Захватывается и звук экрана, когда браузер его отдаёт.

**Админ-панель.** `/admin` — сводка по базе, таблицы пользователей, комнат,
каналов, участников и сообщений. Любую запись можно открыть, отредактировать
по полям, удалить или создать новую. Пароли задаются отдельным полем и
сохраняются хешем. Отдельно есть SQL-консоль, если правку удобнее сделать
запросом.

## Про сеть

Браузеры дают доступ к микрофону и экрану только в защищённом контексте:
`localhost` работает всегда, по локальной сети или из интернета нужен HTTPS.
Поэтому для доступа с других устройств запускайте с `--ssl` (браузер
предупредит про самоподписанный сертификат — это ожидаемо).

Медиа идут напрямую между браузерами. Внутри одной сети этого достаточно.
Если участники за строгим NAT и звук не проходит, нужен TURN-сервер:
см. [DEPLOYMENT.md](DEPLOYMENT.md). Кнопка «На связи» открывает диагностику.

Mesh-схема означает, что каждый шлёт свой поток каждому. Для разговора на
4–6 человек это нормально, для трансляции экрана в большой компании нагрузка
на отдающего растёт линейно — тут уже нужен SFU.

## Мелочи, о которых стоит знать

- Сервер работает в потоковом режиме. Состояние голосовых комнат находится
  в памяти одного процесса: запуск нескольких workers требует переработки
  этого состояния. Настройка reverse proxy описана в [DEPLOYMENT.md](DEPLOYMENT.md).
- Удаление пользователя в админке уносит его сообщения и участия, но комнаты,
  которые он создал, остаются с пустым владельцем.
- Заблокированный пользователь (`is_banned`) не войдёт и будет отключён от
  текущей сессии при следующем запросе.

## Локальные регрессионные проверки

Зависимости для проверки (виртуальное окружение уже создано при аудите):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q tests/test_server.py
```

Проверка интерфейса и реального WebRTC в установленном Microsoft Edge:

```powershell
# Терминал 1: отдельная временная база, только 127.0.0.1:2080
.\.venv\Scripts\python.exe tests/local_server.py

# Терминал 2: браузерные сценарии с синтетическим микрофоном и экраном
.\.venv\Scripts\python.exe tests/browser_check.py

# Отдельный сценарий отсутствия медиамаршрута, около 40 секунд
.\.venv\Scripts\python.exe tests/network_failure_check.py
```

Тестовые пользователи `alice`, `boris`, `vera`; пароль каждого —
`local-test-only`. Их данные существуют только во временной тестовой базе.
Отчёты и снимки интерфейса сохраняются в `artifacts/`. Личные микрофон,
рабочий стол и браузерный профиль не используются.

Для изолированного запуска обычного `main.py` можно задать
`EFIR_INSTANCE_DIR` — каталог для тестовой базы, сертификата и ключа сессий.
Без этой переменной приложение использует прежний `instance/`.

Приложение больше не зависит от CDN Socket.IO и Google Fonts:
Socket.IO 4.7.5 хранится в `app/static/vendor/` с исходным заголовком MIT,
шрифты берутся из системы. Публичные STUN нужны только для нахождения
внешнего маршрута; локальные соединения могут работать без интернета.
