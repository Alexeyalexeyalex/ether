# Эфир на Windows 10: ноутбук, nginx и домашний роутер

Сайт обслуживают nginx и `main.py` на ноутбуке. Для голоса между сетями
добавляется отдельный coturn на том же ноутбуке. Роутер направляет его порты
непосредственно на ноутбук; существующий HTTP proxy в nginx менять не нужно.

Это инструкция для установки **на серверном ноутбуке**. Установка WSL,
coturn, изменение брандмауэра и роутера в ходе локальной проверки проекта
не выполнялись. Пример конфигурации сам по себе TURN не запускает.

## 1. Адреса и порты

Узнайте IPv4 ноутбука через `ipconfig` и закрепите его в DHCP роутера.
В примерах `192.168.1.50` — этот локальный адрес, `203.0.113.10` — пример
публичного IPv4 роутера. **Оба значения нужно заменить реальными.**
WAN-адрес в панели роутера должен быть публичным: при CGNAT обычного
проброса недостаточно, понадобится публичный адрес у провайдера или
отдельный TURN с публичным адресом.

Домен `xn--h1aqk9a.space` — ASCII-запись `эфир.space`. Его DNS A-запись
должна вести на публичный IP роутера без HTTP/CDN-проксирования.
Можно использовать отдельное имя TURN с такой же A-записью.

Добавьте в роутере правила NAT / Port Forwarding, сохраняя номера портов:

| Внешние порты | Протокол | Адрес назначения | Внутренние порты |
|---|---|---|---|
| 3478 | UDP | IPv4 ноутбука | 3478 |
| 3478 | TCP | IPv4 ноутбука | 3478 |
| 49160–49260 | UDP | IPv4 ноутбука | 49160–49260 |

Диапазон UDP нужен и при подключении браузера к TURN по TCP.
HTTPS-порты сайта остаются как настроены. DMZ и отключение брандмауэра
не требуются. При смене внешнего IP обновляйте и DNS, и `external-ip` ниже.

## 2. WSL 1 и coturn

Для этого варианта используется **WSL 1**: приложения доступны через сеть
Windows. У WSL 2 на Windows 10 отдельная сеть NAT; одного `netsh portproxy`
для этого UDP-трафика недостаточно. Это следует из
[описания сети WSL](https://learn.microsoft.com/en-us/windows/wsl/networking).

В PowerShell **от администратора** на серверном ноутбуке:

```powershell
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
```

Если компонент включён впервые, перезагрузите Windows в удобный момент.
После перезагрузки установите отдельную Ubuntu 22.04:

```powershell
wsl --set-default-version 1
wsl --install -d Ubuntu-22.04
wsl --list --verbose
```

При первом запуске Ubuntu создайте её пользователя. В списке WSL напротив
Ubuntu-22.04 должна стоять версия `1`. Если новая Ubuntu установилась как `2`:

```powershell
wsl --set-version Ubuntu-22.04 1
wsl -d Ubuntu-22.04
```

Если старый Windows не знает `wsl --install`, установите Ubuntu 22.04 из
Microsoft Store после включения компонента. См.
[ручную установку WSL](https://learn.microsoft.com/en-us/windows/wsl/install-manual)
и [команды WSL](https://learn.microsoft.com/en-us/windows/wsl/basic-commands).

В открытой **Ubuntu**:

```bash
sudo apt update
sudo apt install -y coturn
sudo service coturn stop
turnserver --version
```

Создайте случайный секрет **на своём сервере**:

```bash
openssl rand -hex 32
```

Скопируйте его в два конфигурационных файла ниже. Не отправляйте его в чат.

## 3. Настройка coturn

В Ubuntu сохраните исходную конфигурацию и откройте редактор:

```bash
sudo cp -n /etc/turnserver.conf /etc/turnserver.conf.before-efir
sudo nano /etc/turnserver.conf
```

Замените содержимое примером из [turn.windows.conf.example](turn.windows.conf.example).
Задайте локальный IP ноутбука в `listening-ip` и `relay-ip`, пару
`ПУБЛИЧНЫЙ_IP/ЛОКАЛЬНЫЙ_IP` в `external-ip` и сгенерированный секрет
в `static-auth-secret`. Не добавляйте `no-auth` или статический `user=`.
В coturn 4.18+ удалите строки `no-cli` и `no-dtls`: эти флаги удалены,
соответствующие функции теперь выключены по умолчанию.

Сохраните файл (Ctrl+O, Enter, Ctrl+X) и ограничьте чтение:

```bash
sudo chown root:turnserver /etc/turnserver.conf
sudo chmod 640 /etc/turnserver.conf
```

Для первого запуска оставьте coturn в отдельном окне Ubuntu:

```bash
sudo turnserver -c /etc/turnserver.conf --log-file=stdout
```

Проверьте отсутствие ошибок привязки адресов и занятых портов.
Это обычный процесс: при его остановке TURN пропадёт; после перезапуска
Windows его нужно запускать снова. В WSL 1 не используйте `systemctl`.
Ноутбук не должен уходить в сон во время работы сервера.

## 4. Брандмауэр Windows

В отдельном PowerShell **от администратора** добавьте только эти правила:

```powershell
New-NetFirewallRule -DisplayName 'Efir TURN UDP' -Direction Inbound -Action Allow -Protocol UDP -LocalPort 3478,49160-49260
New-NetFirewallRule -DisplayName 'Efir TURN TCP' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 3478
```

Правила добавляются один раз. Если такие правила уже есть, проверьте их,
а не создавайте дубликаты. Проброс портов на роутере из шага 1 тоже нужен.

## 5. Настройка Эфира и привычный запуск main.py

Перенесите обновлённый `app/rtc_config.py` на сервер. Скопируйте
[turn.json.example](turn.json.example) в `instance/turn.json` рядом с базой
Эфира и замените `secret` **тем же значением**, что в `static-auth-secret`.
При другом TURN-домене измените оба URL. Файл должен остаться JSON в UTF-8
(BOM поддерживается), без комментариев; проверьте, что Блокнот не добавил `.txt`.

Это приватный файл: каталог `instance/` уже исключён из Git. Не размещайте
его в static или в каталоге, который nginx отдаёт как файлы. Ограничьте доступ
на Windows учётной записью, запускающей приложение, и администраторами.
В браузеры уходят только временные пароли, общий `secret` не отправляется.

Запуск остаётся прежним:

```powershell
python main.py
```

Сохраняйте существующие параметры HTTP/HTTPS и nginx. После обновления кода
перезапустите один процесс приложения. Изменения `turn.json` подхватываются
при новом входе в голосовой канал.

Если процессу уже задан `EFIR_TURN_URLS`, он имеет приоритет над файлом:
вся TURN-запись берётся из переменных окружения, без смешивания паролей
из двух источников. Пустой `EFIR_TURN_URLS` отключает загрузку файла.
Удалите старую переменную из окружения запуска, если переходите на файл.
Массив `ice_servers` в `settings.json` продолжает действовать отдельно.
При `EFIR_INSTANCE_DIR` файл ищется в указанном каталоге данных.

## 6. TLS и ограничения сетей

Базовый пример включает TURN UDP и TCP на 3478. Для сетей, блокирующих этот
порт или допускающих только TLS, добавьте TURN TLS с доверенным сертификатом:
уберите `no-tls`, задайте `tls-listening-port=5349`, пути `cert` и `pkey`
внутри Ubuntu, откройте и пробросьте `5349/TCP`, добавьте в `urls`
`turns:xn--h1aqk9a.space:5349?transport=tcp`.

Сертификат должен соответствовать TURN-имени. Coturn читает его самостоятельно:
наличие сертификата только в nginx не включает TLS для TURN. После обновления
сертификата coturn нужно перечитать/перезапустить. В особо строгих сетях может
потребоваться TLS на 443: тот же IP:443 уже занимает nginx, поэтому просто
назначать этот порт coturn нельзя — нужен отдельный IP либо отдельный TURN.

## Что можно проверить

После входа в приложение окно «На связи» должно показывать наличие TURN.
Это подтверждает загрузку настроек, **а не доступность ретранслятора**.
Отсутствие ошибки JSON и открытый TCP-порт также не доказывают передачу звука.

Локальные тесты приложения проверяют выдачу временных паролей и работу WebRTC
между локальными браузерами. Реальная связь через NAT зависит от работающего
coturn, проброса обоих типов портов и внешней сети. После установки для её
подтверждения понадобится отдельно разрешённая проверка: два клиента из
разных сетей, полученные аудиопакеты и маршрут «TURN» в диагностике, если
использован ретранслятор. Такая удалённая проверка здесь не выполнялась.
